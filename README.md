# Formal PDF Engine

A reusable, formal A4 PDF generation engine built on top of **PDFKit** for Node.js.

This engine is designed to produce professional, restrained, print-oriented documents such as:

- Research reports
- Academic-style reports
- Business reports
- Formal reports
- Proposals
- Briefing documents
- White papers
- Policy documents
- Official letters
- Statements
- Technical reports
- Research summaries
- Multi-page formal documents

The engine abstracts away low-level PDFKit layout work and provides a clean, AI-friendly document API.

---

## Requirements

- Node.js 20 or newer
- npm
- Font files placed in `src/fonts/`

Current expected fonts:

```text
src/fonts/
├── Inter-VariableFont_opsz,wght.ttf
├── Inter-Italic-VariableFont_opsz,wght.ttf

└── Merriweather-Italic-VariableFont_opsz,wdth,wght.ttf

The default formal theme uses Merriweather as the main body font.

## Output Behavior

If the output path is a bare filename, the PDF is placed in the `output/` directory.

Example:

```bash
node pdf.js samples/research-report.js --output report.pdf
```

Produces:

```text
output/report.pdf
```

To write to the current directory instead:

```bash
node pdf.js samples/research-report.js --output ./report.pdf
```

If no output path is provided, the CLI uses the document file name and writes to `output/`.

Example:

```bash
node pdf.js samples/research-report.js
```

Produces something like:

```text
output/research-report.pdf
```

## Recommended Document Format

The best document format is a managed CommonJS module.

```js
module.exports = {
  output: "example-report.pdf",

  document: {
    title: "Example Report",
    subtitle: "Optional Subtitle",
    author: "Author Name",
    organization: "Organization Name",
    date: "August 2026",
    confidential: false,
    theme: "formal"
  },

  build(doc) {
    doc.cover();

    doc.heading(1, "Executive Summary");
    doc.paragraph("Content goes here.");

    doc.heading(1, "1. Introduction");
    doc.paragraph("More content goes here.");
  }
};
```

The CLI creates the document, calls `build(doc)`, and saves the PDF.

Managed document modules should **not** call `doc.save()`.

## Full Report Example

```js
module.exports = {
  output: "ai-impact-research-report.pdf",

  document: {
    title: "The Impact of Artificial Intelligence",
    subtitle: "A Formal Research Summary",
    author: "Research Department",
    organization: "Research Division",
    date: "August 2026",
    theme: "formal"
  },

  build(doc) {
    doc.cover();

    doc.heading(1, "Executive Summary");

    doc.paragraph(
      "Artificial intelligence has significantly affected research, operations, " +
      "and document production workflows. This report summarizes the main findings " +
      "in a formal and restrained manner."
    );

    doc.heading(1, "1. Introduction");

    doc.paragraph(
      "This section introduces the topic and outlines the scope of the report."
    );

    doc.heading(2, "1.1 Background");

    doc.paragraph(
      "Automated document generation has become increasingly important for " +
      "organizations that produce formal reports at scale."
    );

    doc.heading(2, "1.2 Objectives");

    doc.bullets([
      "Assess the operational impact of automation",
      "Review document quality requirements",
      "Identify risks and limitations"
    ]);

    doc.heading(1, "2. Findings");

    doc.paragraph(
      "The findings indicate that structured layout engines improve consistency " +
      "and reduce manual formatting effort."
    );

    doc.table({
      caption: "Summary of findings",
      headers: ["Area", "Finding", "Confidence"],
      rows: [
        ["Operations", "Formatting overhead is reduced", "High"],
        ["Quality", "Output consistency improves", "High"],
        ["Governance", "Review workflows remain necessary", "Medium"]
      ],
      columnWidths: [1, 3, 1],
      zebra: true
    });

    doc.heading(1, "3. Conclusion");

    doc.paragraph(
      "The evidence supports continued use of structured formal document pipelines."
    );

    doc.references([
      "Research Division. Internal Automation Review. 2026.",
      "Document Systems Group. Formal Layout Principles. 2025."
    ]);
  }
};
```

## Document Metadata

Supported metadata fields inside the `document` object:

```js
document: {
  title: "Document Title",
  subtitle: "Optional subtitle",
  author: "Author Name",
  organization: "Organization Name",
  date: "August 2026",
  confidential: false,
  confidentiality: "CONFIDENTIAL",
  theme: "formal",
  styles: {}
}
```

Notes:

- `title` is used for the PDF metadata and default footer.
- `subtitle` is used on the cover page when present.
- `organization` is used in the default header when present.
- `date` is a human-readable string.
- `confidential: true` automatically sets `CONFIDENTIAL`.
- `confidentiality` can be used for a custom confidentiality label.
- `theme` controls the visual theme.
- `styles` allows limited style overrides.

## Available Document Methods

Inside `build(doc)`, the following methods are available.

---

### Cover Page

```js
doc.cover();
```

Optional override:

```js
doc.cover({
  title: "Custom Cover Title",
  subtitle: "Custom Subtitle",
  author: "Custom Author",
  date: "August 2026"
});
```

The cover page should be the first content element.

---

### Enhanced Cover Page

The cover page also supports branding and metadata rows.

```js
doc.cover({
  logo: "assets/logo.png",
  version: "1.0.0",
  status: "Final",
  reference: "ENG-2026-014",
  meta: [
    {
      label: "Project",
      value: "Formal PDF Engine"
    },
    {
      label: "Owner",
      value: "Platform Team"
    }
  ]
});
```

Supported cover options:

```js
title
subtitle
author
organization
date
preparedByLabel
logo
logoWidth
version
status
reference
meta
compactMeta
```

Rules:

- Use `logo` only if the user provides a logo path or buffer.
- Do not invent logo paths.
- Use `version`, `status`, and `reference` only when relevant.
- Keep cover metadata concise.
- `meta` must be an array of strings or objects with `label` and `value`.

Example:

```js
doc.cover({
  meta: [
    "Distribution: Internal",
    {
      label: "Department",
      value: "Engineering"
    }
  ]
});
```

doc.heading(1, "Major Section");

doc.paragraph("Paragraph text.");

```js

```

### Blockquotes

```js

```

---

### Bulleted Lists

```js
doc.bullets([
  "First point",

  {
    text: "Parent point",
    children: [

    ]
  }

```

### Numbered Lists

```js
doc.numbered([
  "First step",
  "Second step",
  "Third step"

```

Optional start number:

```js
doc.numbered(items, {
  start: 1

```

---

### Tables

```js
doc.table({
  headers: ["Column A", "Column B", "Column C"],
  rows: [
    ["Value", "Value", "Value"],
    ["Value", "Value", "Value"]
  ]
});
```

Advanced table options:

```js
doc.table({
  caption: "Summary of findings",
  headers: ["Column A", "Column B", "Column C"],
  rows: [
    ["Value", "Value", "Value"]
  ],
  columnWidths: [1, 2, 1],
  aligns: ["left", "left", "right"],
  rowRules: true,
  zebra: true
});
```

Rules:

- Every row must have the same number of columns as `headers`.
- `columnWidths` must have the same length as `headers`.
- `columnWidths` are relative weights.
- `aligns` values must be one of:

```js
"left"
"center"
"right"
```

- Table cells may be strings, numbers, booleans, `null`, or objects:

```js
{
  text: "Cell text",
  align: "right"
}
```

Table captions are supported:

```js
doc.table({
  caption: "Summary of findings",
  headers: ["Area", "Status"],
  rows: [
    ["Operations", "Stable"]
  ]
});
```

Table captions are automatically numbered as:

```text
Table 1. Summary of findings
Table 2. Additional findings
```

To disable automatic table labeling:

```js
doc.table({
  caption: "Unnumbered table caption",
  autoLabel: false,
  headers: ["A", "B"],
  rows: [
    ["Value", "Value"]
  ]
});
```

---

### References

```js
doc.references([
  "Author. Title. Publisher, 2025.",

```

Custom heading:

```js
doc.references(items, {

Structured references are supported:

```

    right: "{date}"

  footer: {
    left: "{title}",
    center: "",

```

Supported template tokens:

```text
{title}
{author}
{organization}
{date}
{confidentiality}
{page}
{totalPages}
```

Disable header:

```js
document: {
  header: false
}
```

Disable footer:

```js
document: {
  footer: false
}
```

## Troubleshooting

### Font not found

Ensure the font files exist exactly under:

```text
src/fonts/
```

The engine expects the exact font file names listed in the Requirements section.

---

### Image not found

Use one of the following:

- An absolute path
- A path relative to the current working directory
- A Buffer containing PNG or JPEG data

Example:

```js
doc.figure("assets/sample.png");
```

---

### Blank first page

Ensure `doc.cover()` is called before any other content if you want a cover page.

Correct:

```js
build(doc) {
  doc.cover();
  doc.heading(1, "Executive Summary");
}
```

Incorrect:

```js
build(doc) {
  doc.heading(1, "Executive Summary");
  doc.cover();
}
```

---

### Table errors

Table row length must match header length.

Correct:

```js
doc.table({
  headers: ["A", "B"],
  rows: [
    ["Value", "Value"]
  ]
});
```

Incorrect:

```js
doc.table({
  headers: ["A", "B"],
  rows: [
    ["Only one value"]
  ]
});
```

---

### AI-generated script fails

Ensure the AI generated a managed module:

```js
module.exports = {
  output: "example.pdf",
  document: { ... },
  build(doc) { ... }
};
```

The generated script should not call:

```js
doc.save();
```

It should not import PDFKit directly.

It should not use manual coordinates.

It should only use the documented high-level API.
```

## Available Document Methods

The `doc` object provided to `build(doc)` supports the following methods.

---

### Cover Page

```js
doc.cover();
```

Use this only as the first content element.

Use it for reports, white papers, research documents, proposals, and formal briefing documents.

Do not use it for simple letters unless the user explicitly asks for a cover page.

Optional override:

```js
doc.cover({
  title: "Custom Cover Title",
  subtitle: "Custom Subtitle",
  author: "Custom Author",
  date: "August 2026"
});
```

---

### Enhanced Cover Page

```js
doc.cover({
  logo: "assets/logo.png",

    {
      label: "Project",
      value: "Document Engine"
    },
    {
      label: "Owner",

  ]

Rules:

- Use `logo` only if the user provides a logo path or buffer.
- Do not invent logo paths.
- Use `version`, `status`, and `reference` only when relevant.
- Keep cover metadata concise.
- Do not invent cover metadata.

---

### Headings

```js
doc.heading(1, "Section Title");
doc.heading(2, "Subsection Title");
doc.heading(3, "Minor Subsection Title");
```

Rules:

- Use level 1 for major sections.
- Use level 2 for subsections.
- Use level 3 for minor subsections.
- Do not use level 4.
- Do not use empty headings.
- If the user wants numbered sections, include the numbers manually in the heading text.

Example:

```js
doc.heading(1, "1. Introduction");
doc.heading(2, "1.1 Background");
doc.heading(2, "1.2 Objectives");
```

---

### Paragraphs

```js
doc.paragraph("Paragraph text.");

Default paragraph text is justified.

```js
doc.paragraph("Paragraph text.", {

});
```

Supported alignment values:

```js
"justify"
"left"
"center"
"right"
```

Rules:

- Use normal prose.
- Avoid excessive whitespace.
- Do not insert manual page breaks unless logically necessary.
- Do not use Markdown syntax such as `**bold**` or `_italic_`.

---

### Blockquotes

```js
doc.quote("Quoted text.");

Use for excerpts, formal statements, or highlighted quotations.

  "First step",
  "Second step",
  "Third step"
]);
```

Optional:

```js
doc.numbered(items, {
  start: 1
});
```

### Tables

```js
doc.table({
  headers: ["Column A", "Column B", "Column C"],
  rows: [
    ["Value", "Value", "Value"],
    ["Value", "Value", "Value"]
  ]
});
```

Optional table configuration:

```js
doc.table({
  caption: "Summary of findings",
  headers: ["Column A", "Column B", "Column C"],
  rows: [
    ["Value", "Value", "Value"]
  ],
  columnWidths: [1, 2, 1],
  aligns: ["left", "left", "right"],
  rowRules: true,
  zebra: true
});
```

Rules:

- Every row must have the same number of columns as `headers`.
- `columnWidths` must have the same length as `headers`.
- `columnWidths` are relative weights, not absolute pixels.
- `aligns` values must be one of:

```js
"left"
"center"
"right"
```

- Table cells may be strings, numbers, booleans, `null`, or objects:

```js
{
  text: "Cell text",
  align: "right"
}
```

- Do not place lists, images, or complex objects inside table cells.
- Use short formal table captions.
- Use zebra rows only when they improve readability.

### References

```js
doc.references([
  "Author. Title. Publisher, 2025.",
  "Organization. Report Name. 2026."

Options:

```js
doc.references(items, {
  heading: "References",
  headingLevel: 1
});
```

No heading:

```js
doc.references(items, {
  heading: false
});
```

Structured references are supported:

```js
doc.references([
  {
    author: "A. Author",
    title: "Document Title",
    publisher: "Publisher",
    year: 2026
  },
  {
    authors: ["A. Author", "B. Author"],
    title: "Another Title",
    publisher: "Publisher",
    year: 2025,
    url: "https://example.com",
    accessed: "August 2026"
  }
]);
```

Rules:

- Do not fabricate sources unless explicitly instructed.
- If no sources are provided, omit references unless the user asks for placeholders.
- Use plain citation strings if citation style is not specified.

## Formal Writing Rules

Unless the user asks otherwise:

- Use a formal, professional tone.
- Use clear section hierarchy.
- Avoid marketing language.
- Avoid decorative language.
- Avoid emojis.
- Avoid excessive exclamation marks.
- Use concise paragraphs.
- Prefer structured sections.
- Prefer readable lists over dense walls of text.
- Keep tables clean and simple.
- Keep captions short.

---

## Default Report Structure

For formal reports, prefer this structure:

```js
build(doc) {
  doc.cover();

  doc.heading(1, "Executive Summary");
  doc.paragraph("...");

  doc.heading(1, "1. Introduction");
  doc.paragraph("...");

  doc.heading(2, "1.1 Background");
  doc.paragraph("...");

  doc.heading(2, "1.2 Objectives");
  doc.bullets([
    "Objective one",
    "Objective two"
  ]);

  doc.heading(1, "2. Findings");
  doc.paragraph("...");

  doc.table({
    caption: "Summary of findings",
    headers: ["Category", "Finding", "Evidence"],
    rows: [
      ["Category A", "Finding A", "Evidence A"],
      ["Category B", "Finding B", "Evidence B"]
    ]
  });

  doc.heading(1, "3. Conclusion");
  doc.paragraph("...");

  doc.references([
    "Source one.",
    "Source two."
  ]);
}
```

## Formal Letter Structure

For letters, usually do not use a cover page.

```js
build(doc) {

      align: "left"
    }
  );

  doc.paragraph(
    "Body paragraph.",
    {
      align: "left"
    }
  );

    align: "left"
  });

  doc.paragraph("Sender Name", {
    align: "right"
  });

    align: "right"
  });
}
```

## Self-Check Before Responding

Before outputting the final JavaScript module, verify:

1. `module.exports` exists.
2. `output` is a kebab-case `.pdf` filename.
3. `document` is an object.
4. `document.title` exists.
5. `build(doc)` exists and is a function.
6. No call to `doc.save()` exists.
7. No PDFKit import exists.
8. No unsupported method is used.
9. All table rows match header length.
10. All heading levels are 1, 2, or 3.
11. All list items are valid strings or objects.
12. All references are valid strings or supported objects.
13. The code is valid CommonJS.
14. The document is formal and professional.
15. The output contains only JavaScript code unless the user asked for explanation.

## Full Report Example

```js
module.exports = {
  output: "ai-impact-research-report.pdf",

  document: {
    title: "The Impact of Artificial Intelligence",
    subtitle: "A Formal Research Summary",
    author: "Research Department",
    organization: "Research Division",
    date: "August 2026",
    theme: "formal"
  },

  build(doc) {
    doc.cover();

    doc.heading(1, "Executive Summary");

    doc.paragraph(
      "Artificial intelligence has significantly affected research, operations, " +
      "and document production workflows. This report summarizes the main findings " +
      "in a formal and restrained manner."
    );

    doc.heading(1, "1. Introduction");

    doc.paragraph(
      "This section introduces the topic and outlines the scope of the report."
    );

    doc.heading(2, "1.1 Background");

    doc.paragraph(
      "Automated document generation has become increasingly important for " +
      "organizations that produce formal reports at scale."
    );

    doc.heading(2, "1.2 Objectives");

    doc.bullets([
      "Assess the operational impact of automation",
      "Review document quality requirements",
      "Identify risks and limitations"
    ]);

    doc.heading(1, "2. Findings");

    doc.paragraph(
      "The findings indicate that structured layout engines improve consistency " +
      "and reduce manual formatting effort."
    );

    doc.table({
      caption: "Summary of findings",
      headers: ["Area", "Finding", "Confidence"],
      rows: [
        ["Operations", "Formatting overhead is reduced", "High"],
        ["Quality", "Output consistency improves", "High"],
        ["Governance", "Review workflows remain necessary", "Medium"]
      ],
      columnWidths: [1, 3, 1],
      zebra: true
    });

    doc.heading(1, "3. Conclusion");

    doc.paragraph(
      "The evidence supports continued use of structured formal document pipelines."
    );

    doc.references([
      "Research Division. Internal Automation Review. 2026.",
      "Document Systems Group. Formal Layout Principles. 2025."
    ]);
  }
};
