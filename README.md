# Formal PDF Engine

A reusable, formal A4 PDF generation engine built on top of **PDFKit** for Node.js.

This engine is designed to produce professional, restrained, black-and-white documents such as:

- Research reports
- Academic-style reports
- Business reports
- Formal reports
- Proposals
- Briefing documents
- White papers
- Policy documents
- Official letters
- Statements
- Technical reports
- Research summaries
- Multi-page formal documents

The engine abstracts away low-level PDFKit layout work and provides a clean, AI-friendly document API.

---

## Requirements

- Node.js 20 or newer
- npm
- Font files placed in `src/fonts/`

Current expected fonts:

```text
src/fonts/
├── Inter-VariableFont_opsz,wght.ttf
├── Inter-Italic-VariableFont_opsz,wght.ttf
├── SpaceGrotesk-VariableFont_wght.ttf
├── Merriweather-VariableFont_opsz,wdth,wght.ttf
└── Merriweather-Italic-VariableFont_opsz,wdth,wght.ttf
```

The default formal theme uses Merriweather as the main body font.

## Output Behavior

If the output path is a bare filename, the PDF is placed in the `output/` directory.

Example:

```bash
node pdf.js samples/research-report.js --output report.pdf
```

Produces:

```text
output/report.pdf
```

To write to the current directory instead:

```bash
node pdf.js samples/research-report.js --output ./report.pdf
```

If no output path is provided, the CLI uses the document file name and writes to `output/`.

Example:

```bash
node pdf.js samples/research-report.js
```

Produces something like:

```text
output/research-report.pdf
```

## Recommended Document Format

The best document format is a managed CommonJS module.

```js
module.exports = {
    output: "example-report.pdf",

    document: {
        title: "Example Report",
        subtitle: "Optional Subtitle",
        author: "Author Name",
        organization: "Organization Name",
        date: "August 2026",
        confidential: false
    },

    build(doc) {
        doc.cover();

        doc.heading(1, "Executive Summary");

        doc.paragraph("Content goes here.");

        doc.heading(1, "1. Introduction");

        doc.paragraph("More content goes here.");
    }
};
```

The CLI creates the document, calls `build(doc)`, and saves the PDF.

Managed document modules should **not** call `doc.save()`.

## Full Report Example

```js
module.exports = {
    output: "ai-impact-research-report.pdf",

    document: {
        title: "The Impact of Artificial Intelligence",
        subtitle: "A Formal Research Summary",
        author: "Research Department",
        organization: "Research Division",
        date: "August 2026"
    },

    build(doc) {
        doc.cover();

        doc.heading(1, "Executive Summary");

        doc.paragraph(
            "Artificial intelligence has significantly affected research, operations, " +
            "and document production workflows. This report summarizes the main findings " +
            "in a formal and restrained manner."
        );

        doc.heading(1, "1. Introduction");

        doc.paragraph(
            "This section introduces the topic and outlines the scope of the report."
        );

        doc.heading(2, "1.1 Background");

        doc.paragraph(
            "Automated document generation has become increasingly important for " +
            "organizations that produce formal reports at scale."
        );

        doc.heading(2, "1.2 Objectives");

        doc.bullets([
            "Assess the operational impact of automation",
            "Review document quality requirements",
            "Identify risks and limitations"
        ]);

        doc.heading(1, "2. Findings");

        doc.paragraph(
            "The findings indicate that structured layout engines improve consistency " +
            "and reduce manual formatting effort."
        );

        doc.table({
            headers: ["Area", "Finding", "Confidence"],
            rows: [
                ["Operations", "Formatting overhead is reduced", "High"],
                ["Quality", "Output consistency improves", "High"],
                ["Governance", "Review workflows remain necessary", "Medium"]
            ],
            columnWidths: [1, 3, 1]
        });

        doc.heading(1, "3. Conclusion");

        doc.paragraph(
            "The evidence supports continued use of structured formal document pipelines."
        );

        doc.references([
            "Research Division. Internal Automation Review. 2026.",
            "Document Systems Group. Formal Layout Principles. 2025."
        ]);
    }
};
```

## Document Metadata

Supported metadata fields inside the `document` object:

```js
document: {
    title: "Document Title",
    subtitle: "Optional subtitle",
    author: "Author Name",
    organization: "Organization Name",
    date: "August 2026",
    confidential: false,
    confidentiality: "CONFIDENTIAL"
}
```

Notes:

- `title` is used for the PDF metadata and default footer.
- `subtitle` is used on the cover page when present.
- `organization` is used in the default header when present.
- `date` is a human-readable string.
- `confidential: true` automatically sets `CONFIDENTIAL`.
- `confidentiality` can be used for a custom confidentiality label.

## Available Document Methods

Inside `build(doc)`, the following methods are available.

### Cover Page

```js
doc.cover();
```

Optional override:

```js
doc.cover({
    title: "Custom Cover Title",
    subtitle: "Custom Subtitle",
    author: "Custom Author",
    date: "August 2026"
});
```

The cover page should be the first content element.

---

### Headings

```js
doc.heading(1, "Major Section");
doc.heading(2, "Subsection");
doc.heading(3, "Minor Subsection");
```

Heading levels currently supported:

```text
1
2
3
```

If section numbering is required, include it manually:

```js
doc.heading(1, "1. Introduction");
doc.heading(2, "1.1 Background");
doc.heading(2, "1.2 Objectives");
```

---

### Paragraphs

```js
doc.paragraph("Paragraph text.");
```

Default paragraph alignment is justified.

Left-aligned paragraph:

```js
doc.paragraph("Paragraph text.", {
    align: "left"
});
```

Supported alignment values:

```js
"justify"
"left"
"center"
"right"
```

---

### Blockquotes

```js
doc.quote("Quoted text.");
```

---

### Bulleted Lists

```js
doc.bullets([
    "First point",
    "Second point",
    {
        text: "Parent point",
        children: [
            "Nested point"
        ]
    }
]);
```

---

### Numbered Lists

```js
doc.numbered([
    "First step",
    "Second step",
    "Third step"
]);
```

Optional start number:

```js
doc.numbered(items, {
    start: 1
});
```

---

### Tables

```js
doc.table({
    headers: ["Column A", "Column B", "Column C"],
    rows: [
        ["Value", "Value", "Value"],
        ["Value", "Value", "Value"]
    ]
});
```

Advanced table options:

```js
doc.table({
    headers: ["Column A", "Column B", "Column C"],
    rows: [
        ["Value", "Value", "Value"]
    ],
    columnWidths: [1, 2, 1],
    aligns: ["left", "left", "right"],
    rowRules: true
});
```

Rules:

- Every row must have the same number of columns as `headers`.
- `columnWidths` must have the same length as `headers`.
- `columnWidths` are relative weights.
- `aligns` values must be one of:
  ```js
  "left"
  "center"
  "right"
  ```
- Table cells may be strings, numbers, booleans, `null`, or objects:
  ```js
  {
      text: "Cell text",
      align: "right"
  }
  ```

---

### References

```js
doc.references([
    "Author. Title. Publisher, 2025.",
    "Organization. Report Name. 2026."
]);
```

Custom heading:

```js
doc.references(items, {
    heading: "Bibliography",
    headingLevel: 2
});
```

No heading:

```js
doc.references(items, {
    heading: false
});
```

Structured references are supported:

```js
doc.references([
    {
        author: "A. Author",
        title: "Document Title",
        publisher: "Publisher",
        year: 2026
    },
    {
        authors: ["A. Author", "B. Author"],
        title: "Another Title",
        publisher: "Publisher",
        year: 2025,
        url: "https://example.com",
        accessed: "August 2026"
    }
]);
```

---

### Images and Figures

```js
doc.figure("assets/sample.png", {
    caption: "Figure caption.",
    width: "70%",
    border: true
});
```

Options:

```js
doc.figure(imageSource, {
    caption: "Caption text",
    width: 300,
    align: "center",
    border: true,
    autoLabel: true,
    label: "Figure"
});
```

Supported width values:

```js
300
"75%"
```

Supported alignment values:

```js
"left"
"center"
"right"
```

Images must be PNG or JPEG.

---

### Manual Page Break

```js
doc.pageBreak();
```

Use sparingly. Automatic pagination is preferred.

## Headers and Footers

Headers and footers can be configured in the document metadata.

Example:

```js
document: {
    title: "Report Title",
    organization: "Organization Name",
    date: "August 2026",
    header: {
        left: "{organization}",
        center: "",
        right: "{date}"
    },
    footer: {
        left: "{title}",
        center: "",
        right: "Page {page} of {totalPages}"
    }
}
```

Supported template tokens:

```text
{title}
{author}
{organization}
{date}
{confidentiality}
{page}
{totalPages}
```

Disable header:

```js
document: {
    header: false
}
```

Disable footer:

```js
document: {
    footer: false
}
```

## Page Numbering

Basic page numbering configuration:

```js
document: {
    pageNumbering: {
        start: 1,
        coverPages: 0
    }
}
```

When using `doc.cover()`, the engine automatically treats the cover page as an unnumbered page and starts content page numbering at page 1.

## AI Generation

For AI-generated documents, use:

```text
AI_GENERATION_GUIDE.md
```

That file defines the exact contract an AI should follow when generating document modules for this engine.

Typical workflow:

```text
Read AI_GENERATION_GUIDE.md.

Generate a formal research report about [TOPIC].

Use a cover page, executive summary, introduction, findings, conclusion, and references if appropriate.

Output only the JavaScript document module.
```

Save the AI output as a `.js` file, then run:

```bash
node pdf.js path/to/generated-document.js
```

## Troubleshooting

### Font not found

Ensure the font files exist exactly under:

```text
src/fonts/
```

The engine expects the exact font file names listed in the Requirements section.

---

### Image not found

Use one of the following:

- An absolute path
- A path relative to the current working directory
- A Buffer containing PNG or JPEG data

Example:

```js
doc.figure("assets/sample.png");
```

---

### Blank first page

Ensure `doc.cover()` is called before any other content if you want a cover page.

Correct:

```js
build(doc) {
    doc.cover();

    doc.heading(1, "Executive Summary");
}
```

Incorrect:

```js
build(doc) {
    doc.heading(1, "Executive Summary");

    doc.cover();
}
```

---

### Table errors

Table row length must match header length.

Correct:

```js
doc.table({
    headers: ["A", "B"],
    rows: [
        ["Value", "Value"]
    ]
});
```

Incorrect:

```js
doc.table({
    headers: ["A", "B"],
    rows: [
        ["Only one value"]
    ]
});
```

---

### AI-generated script fails

Ensure the AI generated a managed module:

```js
module.exports = {
    output: "example.pdf",
    document: { ... },
    build(doc) { ... }
};
```

The generated script should not call:

```js
doc.save();
```

It should not import PDFKit directly.

It should not use manual coordinates.

It should only use the documented high-level API.
